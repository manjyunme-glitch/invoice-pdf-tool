# 发票处理工具箱 v6.1.0

一个面向 Windows 的桌面发票工具，用来解决两类高频工作：

- 从复杂 Excel 工作簿中筛选需要的发票号码，再批量匹配并导出本地 PDF 发票
- 按文件名规则整理一批零散 PDF，把它们自动归档到对应公司文件夹

它适合财务、税务、出纳、行政或需要长期处理进项发票、抵扣发票、税局导出表和内部台账的人。

## 下载

- 普通用户：到 GitHub 的 `Releases` 页面下载 EXE
- 开发者：直接克隆本仓库运行源码

如果你只想使用，不需要 Python 环境，直接下载发布页里的 Windows 单文件 EXE 即可。

## 这个工具能做什么

### 1. 发票筛选

- 打开 `.xlsx` / `.xls` 文件
- 识别一个工作簿中的多个 Sheet
- 选择目标 Sheet，提取发票列和公司列
- 在 PDF 目录中匹配同名或对应编号的发票文件
- 先预览，再正式导出
- 导出后自动生成结果报告

### 2. 多 Sheet 工作簿分析

- 展示所有 Sheet 的名称、行列规模和可用状态
- 自动识别候选发票列
- 自动识别候选公司列
- 标记推荐 Sheet
- 给出样本预览，方便确认识别结果

这部分尤其适合“一个 Excel 里混有税局表、抵扣表、内部表、月度台账”的实际场景。

### 3. 行级条件筛选

除了按发票号筛选，还可以继续按其他列缩小范围，例如：

- 只保留“是否抵扣 = 是”的发票
- 排除某些公司名称或脏数据标记
- 按某一列做“等于 / 包含 / 不等于 / 不包含”过滤

支持的模式：

- `不过滤`
- `等于任一`
- `包含任一`
- `不等于任一`
- `不包含任一`

### 4. 自动导出到当前 Excel 目录

支持按“Excel 所在目录 + 当前 Sheet 名称”自动创建导出文件夹。

例如当前 Excel 在：

```text
F:\工作文档\2025年8月
```

当前 Sheet 是：

```text
8月进项
```

那么导出目录会自动变成：

```text
F:\工作文档\2025年8月\8月进项
```

这非常适合：

- 月度进项发票筛选
- 抵扣发票筛选
- 按工作表分组归档 PDF

### 5. 发票整理

- 扫描一个文件夹里的 PDF
- 按文件名分段解析公司名称
- 自动移动到对应公司文件夹
- 支持递归扫描
- 支持预览、勾选、执行、撤销

### 6. 历史记录与回滚

- 查看整理历史
- 查看筛选历史
- 按时间、类型、关键字过滤
- 回滚前校验文件内容指纹，避免删除或移动用户后来替换的同名文件
- 回滚导出结果和关联报告
- 旧版历史记录仍可查看；缺少安全校验信息时不会自动执行破坏性回滚

### 7. 文件安全与中断恢复

- 整理目标必须位于用户选择的根目录内，拒绝 `.`、`..`、Windows 保留名称和路径分隔符
- 每次移动或复制都会记录 SHA-256 内容指纹和受信根目录
- 导出目录已有同名文件时先比较内容：相同则跳过，不同则标记“同名冲突”，不会覆盖原文件
- 同一发票号对应多个 PDF 时标记“重复冲突”并阻止导出，避免随机选中错误文件
- 筛选报告使用临时文件校验后独占发布；同一秒生成多个报告时自动编号，不覆盖已有报告
- 筛选报告包含逐项“处理明细”和各状态汇总；外部文件名或单元格文本会转义，避免被 Excel 误识别为公式
- 递归整理会识别已经位于直接目标公司目录中的文件，重复执行不会继续产生副本
- 任务执行期间关闭窗口时，会先请求取消并等待当前文件安全处理完成
- 整理和筛选任务支持在文件边界暂停 / 继续；当前正在写入的单个文件先安全完成，取消会解除暂停并停止后续处理
- 运行中的文件操作会写入 `%APPDATA%\InvoiceTool\active_task.json`；异常中断后，下次启动会把已完成操作恢复到历史记录
- 配置、历史和任务日志使用临时文件加原子替换保存，降低写入中断导致 JSON 损坏的风险
- 配置或历史 JSON 损坏、编码异常或根节点类型错误时，会先隔离为 `*.corrupt-*.json` 保留原件，再使用安全默认值启动
- 配置文件带有格式版本；导入和恢复默认前会自动备份，未知字段会保留，高于当前版本的配置会进入只读保护而不会被关闭程序时覆盖
- `%APPDATA%` 配置目录不可创建时会降级到系统临时目录并在状态栏、日志和诊断包中提示，避免因目录权限问题直接启动失败

### 8. 桌面工作台体验

- 白天 / 黑夜双主题
- 使用左侧任务导航组织“Excel 筛选、发票整理、任务历史、设置与诊断”，不再依赖顶部标签来回查找
- 默认进入高频的 Excel 筛选工作流，并在页面标题下持续显示当前流程阶段
- 筛选页按“输入 → 规则 → 预览 → 执行 → 结果”形成连续流程，步骤状态随工作簿分析和任务结果实时更新
- 预览、执行、取消、进度和打开导出目录固定在页面底部，滚动检查规则与结果时仍可直接操作
- PDF 扫描、工作簿分析和筛选预览在后台线程运行，不再阻塞 Tk 主线程；期间复用底部进度与取消入口
- 后台读取任务使用启动时的路径与规则快照；若用户中途修改输入，旧结果不会覆盖新上下文
- 取消扫描、分析或预览只停止读取与计算，不会移动、复制或删除文件
- 整理页按“目录 → 扫描 → 确认 → 执行 → 结果”连续展示，扫描摘要会区分可处理、已归档和文件名无效项目
- 整理任务的执行、取消、撤销和进度固定在页面底部；完成或异常恢复后保留结果摘要与撤销入口
- 历史页采用任务列表与详情摘要并排的主从布局，单击记录即可查看目录、文件明细和回滚可信状态
- 整理结果会保留逐文件成功、跳过或失败原因；失败项可定向重试，筛选复制失败可按当前规则安全重跑，已导出且内容一致的文件自动跳过
- 新版历史会保存结果明细、失败数、取消状态和再次执行参数；“再次执行”只载入路径与规则，不会跳过预览或确认直接操作文件
- 异常中断恢复记录会在状态栏和历史详情中明确标记，并继续使用文件指纹保护回滚
- 新记录会显示“可校验回滚”；旧记录、校验信息不完整或结构损坏的记录会明确警告并保护不可信文件
- `Alt + 1…4` 可快速切换四个任务页，导航按钮保留清晰的键盘焦点状态
- 记住最近使用的任务页；旧配置无需迁移，缺少该字段时使用安全默认值
- 窗口和导航尺寸会根据 Tk/Windows DPI 比例调整，适配 125%、150% 和 200% 缩放
- 全局任务状态、进度和运行日志固定在工作台底部
- 结果区域表格化展示
- 设置页和筛选页支持滚动
- 设置页支持配置导入、导出和恢复默认；应用前显示变更预览，并把原配置备份到配置目录下的 `backups` 文件夹
- 诊断中心可导出 ZIP 诊断包，仅包含运行环境、功能能力状态、存储存在性和脱敏后的最近日志，不包含原始配置、历史记录、Excel 或 PDF
- 诊断脱敏会替换本地路径、网络路径和连续长数字；诊断包仍提示用户在发送前人工检查
- 文件日志和界面日志统一脱敏本地路径、网络路径、文档名、邮箱和连续长数字；日志按 2 MB 轮换并最多保留 3 份备份
- 底部日志抽屉支持查看、复制、导出和清空，设置页可导出完整脱敏诊断包
- 切换白天 / 黑夜主题时保留当前筛选或整理步骤和结果上下文
- 切换 Sheet 时自动重置条件筛选，避免误带上一个工作表的过滤条件

## v5.3.0 界面美化与性能优化 (UI Aesthetics & Performance Enhancements)

这一版不仅重构并大幅美化了界面视觉体验，同时也对系统的稳定性和核心交互做出了重要优化。

- **六大界面设计方案美化**：
  - **统一按钮悬停微交互**：对所有次级与辅助按钮（浏览、扫描、重置、分析等）统一扁平化现代设计，绑定 `<Enter>` / `<Leave>` 事件实现柔和的背景色悬停渐变。

  - **卡片式看板设计**：大数值卡片增加 `1px` 微光边框，强化“标签”与“大数值”字号对比度。
  - **融合式无边框容器**：移除所有原生生硬的 `bd=1, relief="solid"` 边框，使用与主题色调相融的 `highlightthickness=1` 进行自然分割。
  - **精致顶栏与胶囊药丸 Badge**：顶栏底部增加 1px 微光分割线，主题状态采用圆角胶囊药丸化设计，按钮适配 `☀️` / `🌙` 标识。
  - **极客风格底座日志**：日志抽屉拉手条增加悬停高亮提示，折叠符号升级为几何符号 `▲` 与 `▼`，控制台日志针对白天与黑夜模式重新渲染主题高对比度色彩。
- **功能优化与缺陷修复**：
  - **修复 DND 拖拽解析 bug**：解决 `_parse_dnd_event_paths` 内部因未正确引用 `event_data` 变量而导致的潜在拖放崩溃错误。
  - **增加段位解析保护**：文件名段位解析加入越界保护，避免异常文件名崩溃。
  - **加强设置页容错**：拦截设置非法输入，避免保存配置时触发 `TclError`。
  - **多路径全局拖拽支持**：Excel 路径、PDF 文件夹、导出目录均已支持拖放输入。
  - **性能飞跃**：大数据量 Excel 工作簿分析效率提升百倍。
  - **历史记录交互升级**：支持双击记录在文件夹中定位，并在详情窗双击文件直接打开。
- **该历史版本打包命名**：`invoice-pdf-tool-v5.3.0-windows-x64.exe`。

## 典型使用场景

### 场景一：筛选进项发票

1. 打开 Excel 文件
2. 选择 `8月进项` 这类 Sheet

5. 预览后执行整理
6. 如有误操作，可撤销

## PDF 命名规则

工具默认通过文件名分段来提取关键字段。

常见格式示例：

```text
dzfp_发票号码_公司名称_日期.pdf
```

默认思路：

- 使用 `_` 作为分隔符
- 在设置中配置“公司名所在段”和“发票号所在段”

如果你的 PDF 命名格式不同，也可以在设置页调整规则预设或手动修改段位。

## Excel 使用建议

工具支持复杂工作簿，但为了得到更稳定的结果，建议注意以下几点：

- 不同 Sheet 的列名可以不一致
- 自动识别不准确时，可以手动指定发票列和公司列
- 如果 Excel 已经把超长发票号按数值存储并丢失精度，任何工具都无法完全还原原始号码
- 最稳妥的做法是尽量让发票号在源表中保持文本格式

## 筛选结果说明

预览和导出后，结果表格中可能出现这些状态：

- `可匹配`
- `未匹配`
- `重复冲突`
- `同名冲突`
- `已导出`
- `已跳过`
- `复制失败`

你还可以：

- 按状态过滤结果
- 用关键字搜索结果
- 打开选中的 PDF
- 复制未匹配发票号

## 打包 EXE

```bash
python -m pip install -r requirements-build.txt
打包为EXE.bat
```

打包脚本会先执行完整回归测试，测试失败时不会生成发布包。脚本只清理本版本的 PyInstaller 工作目录，不会删除整个 `dist` 或其他历史产物。

## 常见问题

### 1. 为什么发票号显示不对？

如果 Excel 源表把长号码当成数值保存，并且已经丢失精度，程序只能尽量避免科学计数法显示，不能凭空恢复被 Excel 截断的真实号码。

### 2. 为什么一个工作簿里有些 Sheet 不可用？

因为并不是每个 Sheet 都包含有效的发票列。工具会尽量识别，但如果一个 Sheet 没有合适列，就会被标记为不可筛选。

### 3. 为什么建议先预览再导出？

因为很多真实表格都混有手工标记、无效行、测试行、异常公司名。先预览可以明显减少误导出。
